# v2.7.17 · 音效（默认关闭）+ 启动图标放大

## 音效：只做两条，且默认关

先说我判断的依据。任务类应用有个反直觉的事实：**用户 90% 的使用场景在安静环境**
（办公室、床上、开会）。音效加错地方，用户第一件事就是去系统设置里关掉整个通知权限。
所以取舍标准是三条：**高频的不加、没有结果的不加、不能用声音代替视觉的不加。**

最终只做两条：

| 事件 | 声音 | 时长 | 音量 |
|---|---|---|---|
| 勾选完成 | 木质感「嗒」 | 110ms | 0.55 |
| 撤销 | 温和的下行 blip | 90ms | 0.40 |

**默认关闭**，`设置 → 音效` 里手动开，开启时立刻播一声试听。
跟随系统静音（`setAudioModeAsync({ playsInSilentMode: false })`）——静音就该是静音。

### 音色是本地合成的

`bench/make-sfx.py` 用纯 stdlib 合成，不引任何外部素材，因此没有版权问题，
两条合计 **8.7KB**（complete 4.8KB + undo 3.9KB），APK 体积几乎不受影响。

- 完成音：1.15kHz 主分音 + 2.6kHz 泛音 + 前 4ms 噪声瞬态 → 木质感，不是电子「叮」
- 撤销音：760 → 342Hz 下行，指数衰减 24ms

### 明确没做的三条

| 事件 | 为什么不做 |
|---|---|
| 新建任务 | 一天几十次，声音会变噪音 |
| 打字音 | 没有任何生产力应用靠这个加分 |
| 同步成功 | 自动同步一天几十次，同样会变噪音 |

### 一条做了又删掉的：「计时结束」

原本还合成了一条三音上行 chime（660ms），准备给「专注计时结束」用。
写到接线那一步才发现——**这个 App 的「专注」页是筛选过的任务列表，根本没有倒计时器**，
没有触发点。于是把 `timer.wav` 连同代码里的 `"timer"` 一起删掉了。

不留永远不会响的音效，也不在设置页写「计时结束会响」这种空承诺。

## 技术备忘

- 依赖：`expo-audio@57.0.5`（**必须 57 线**。先误装了 58.0.12，那是 SDK 58 的）
- Metro 显式兜了一条 `wav` 到 `assetExts`，避免以后有人精简默认列表时音效静默失效
- 播放器按音效懒创建、复用，重复播放先 `seekTo(0)`（否则连点勾选会哑火）
- 所有异常静默吞掉：音效失败绝不能影响主流程
- `previewSfx()` 不看开关，专供设置页试听（那时 kv 还没落盘）
