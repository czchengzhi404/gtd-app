# v2.7.38 · 逻辑审计修复 + 界面一致性

本轮是一次全面质量攻坚：先修已确认的逻辑缺陷，再按流程与界面走查补细节。

## 修复的逻辑缺陷（6 项，均有回归测试）

1. **同步/备份恢复丢失「每周多日」**
   `coerce` 里用字符串数组过滤数字数组 `byWeekday`，`[1,3]` 恒被清空——「每周一三」同步一次就退化成「每周」。
   现在任务与模板共用 `normalizeRecurrence`，并兼容老数据里的字符串数字。

2. **撤销完成丢失原状态**
   `task.uncomplete` 曾硬编码 `projectId ? next : inbox`，`waiting` 任务误勾后撤销会跳到收集箱。
   现在 payload 可带 `restore` 快照，单条撤销与批量撤销都会还原状态。

3. **重复任务撤销后到期日不回退**
   完成时 `dueAt` 推进一个周期、写入 `lastCompletedAt`，撤销却不还原。现在一并回到完成前。

4. **删除前置会让依赖任务永久消失**
   首屏把「已删除的前置」当成未完成，任务静默不可做，而详情页显示「没有未完成前置」。
   现在两处口径一致：已删除 = 已满足；本地查不到的 id 仍按保守语义挡住。

5. **回顾页与统计页完成数对不上**
   重复任务完成时 `completedAt` 被置空，回顾页只认 `completedAt`，于是全部漏计。
   现在两处共用 `completionTime`（`completedAt ?? lastCompletedAt`）。

6. **「每两周」实际每周触发**
   `weekly` 分支里有个恒真的 `||` 分支把 `interval` 短路；且 `anchor` 每次完成都会前进，
   相对自身的周次永远是 0。现在引入 `originAt` 作为稳定起点（创建/改规则时自动补），
   并让每周重复保留原时刻（此前会掉到 00:00）。

## 流程与界面修复

- **快速添加没有反馈**：有筛选或停在「一张」视角时，新增任务可能完全看不见，用户会以为记录失败。
  现在成功给提示，并在筛选会挡住新任务时自动清空筛选；失败也给出原因。
- **项目页按钮出现两个加号**：「＋ 新建项目」文案自带全角加号，按钮又渲染 add 图标。文案已去掉伪图标字符。
- **统计图 X 轴全是「11/...」**：14 根柱子每根太窄，日期被截断。图轴改为只显示日号，读屏与点击提示仍给完整日期。
- **模板空态文案把「新建」拆成两行**：精简措辞。
- **专注页「今日到期」分组里含逾期任务**：标题改为「今天与逾期」。

## 补充功能

- 任务详情新增重复预设：**每两周**、**每月末工作日**（引擎与快速添加早就支持，界面此前选不到）。
- 重复预设的选中判定纳入 `interval` 与 `lastWeekday`，不再出现「每周 / 每两周」同时高亮。
