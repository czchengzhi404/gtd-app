## 防环：这是先后关系最危险的地方

`A 等 B、B 等 A` 会让两个任务**永远互为未完成前置**，
于是它们静默地从首屏消失 —— 用户只会觉得「东西丢了」，而且查不出原因。

`packages/core/src/features/dependencies.ts` 提供三个纯函数：

| 函数 | 作用 |
|---|---|
| `wouldCreateCycle(tasks, taskId, prereqId)` | 从 `prereqId` 沿「它等谁」走，能走回 `taskId` 就是环 |
| `prereqCandidates(tasks, taskId)` | 排除自己 / 软删 / 会成环的；未完成排前面 |
| `unresolvedPrereqs(task, tasks)` | 还挡着我的（未完成且未删） |

候选列表里根本不显示会成环的选项，所以用户**不可能**把图设成死局。
14 项单测覆盖：自环、两任务互等、长链、菱形、指向不存在的 id、
候选排序、已软删排除。

> 参考 NextTodo 的 `graph.ts`：它用独立边表 + Kahn 拓扑排序去冗余边并声明
> "Dependencies have no cycles"。我们存在任务上，改在**写入前**做可达性检查，
> 代价更小且同样保证无环。
