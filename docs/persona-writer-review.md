# 写作者视角的功能评判与改进路线

> 用户画像：**有主业、业余写作**的爱好者。不是项目经理，不带团队，也不需要企业级流程。
> 他的一天：上班处理杂事 → 晚上/周末写东西（长文、专栏、小说、笔记）→ 偶尔接点活。
> 评判方法：**按他真实的动线走一遍**，看哪一步会被卡住。
> 基线版本：v2.3.0

---

## 0. 一句话结论

> **这是一个做得不错的「任务执行器」，但它目前不是一个能写字的地方。**
>
> 写作者打开它，能记「周五交稿」这种**提醒**，却没有任何地方可以写那篇稿子。
> 这不是取舍，是缺一块。

证据（不是感觉）：

| 事实 | 位置 |
|---|---|
| `notes` 字段只被**只读渲染**（`MarkdownView`），全仓没有任何 `TextInput` 绑定它 | `ui/TaskDetailContent.tsx:243-249` |
| 后端其实**完全支持**写笔记：`task.update` 的 patch 允许 `notes` 最长 100,000 字符 | `models/commands.ts:71` |
| 全仓搜索 `wordCount` / `字数`：**0 命中** | — |
| 深链注释写着支持 `notes=`，代码只读 `title`/`text` | `app/add.tsx` |

也就是说：**能力已经建好了 90%，只是没有门。** 这既是坏消息（当前不可用），也是好消息（补起来很便宜）。

## 1. 评分（满分 5，按写作者的实际需要打）

| 维度 | 分 | 判据 |
|---|---|---|
| **写作本身** | ☆ 0.5 | 没有编辑器。只能写标题（≤2000 字符的单行概念），正文无处可写 |
| **灵感捕获** | ★★☆ 2.5 | 一行能带情境/项目/标签/日期，很快；但只能捕获"一句话"，长一点的念头记不下 |
| **素材与检索** | ★★ 2 | 搜索是子串匹配 + 字段权重排序；没有全文、没有多词 AND、没有"素材"这类实体 |
| **组织** | ★★★☆ 3.5 | 区域→项目→分区→任务 四层很扎实；但缺"文档"这一层——所有内容都必须伪装成任务 |
| **执行** | ★★★★☆ 4.5 | 今天/专注/批量/撤销/手势/番茄钟，完成度很高。这是全项目最强的一块 |
| **回顾** | ★★★ 3 | 每周回顾六步设计得好；但对"我这周写了多少字"毫无感知 |
| **输出** | ★★ 2 | Markdown/ICS/JSON 都能导；但 Markdown 是有损的（丢时刻、标签变项目），恰恰写作者最需要它无损 |
| **数据安全** | ★★★★ 4.5 | 本地优先、软删+回收站、90 天墓碑、备份、可自选网盘同步。可信 |
| **上手成本** | ★★★★ 4 | 三屏引导 + 空态语法片段 + 中英双语，新人友好 |

**加权判断**：如果他是"GTD 爱好者顺便写作"，这 App 值 4 分；如果他是"写作者顺便管任务"，现在只值 2 分——因为**写不了字**。

## 2. 做得高的地方（别动它）

1. **快速添加的解析质量**：`给张总发周报 #工作 @电脑 !! 明天 下午3点 +本周` 一行写完六个属性，且是确定性正则、可测（153 行测试）。这是全项目体验最爽的一处。
2. **执行层闭环完整**：勾选→撤销栈（10 步/60 秒）→ 左滑完成/右滑延后 → 批量完成/移动/推迟 → 番茄钟。每一步都有反馈，破坏性操作都能回退。
3. **数据可靠**：软删 + 回收站 + 墓碑参与同步 + 90 天物理压缩 + 本地备份 7 份。写作者的恐惧是"我写的东西丢了"，这块是及格的。
4. **同步设计克制**：不用注册、填自己网盘、任务还能字段级合并。没有为了"云"去绑架账号。
5. **空态与文案**：`EmptyState` 的 5 种插画 + 可点语法片段，是我见过少数认真做空态的项目。

## 3. 做得低的地方（按危害排序）

### 🩸 3.1 不能写字（致命）

写作者的第一个动作是"打开一个地方写今天的稿"，而这个 App 里：
- 任务只有标题（一行）和 notes（只读展示）
- 想在正文里写 2000 字 → **没有入口**
- 想边写边看渲染效果 → 做不到
- 想知道自己写了多少字 → 没有这个概念

**后果**：他会把 App 当"待办清单"用，写作仍然在 Word/备忘录/Obsidian 里。于是"任务" 和 "内容" 永久分家：清单说"写第三章"，但第三章在别处。**这正好废掉了这个 App 最想做的事——把事和上下文放在一起。**

### 🩸 3.2 没有"文档"这个概念

所有东西都得是任务。但写作者的心智模型是：
- 「一篇稿子」不是任务，是一个**可以反复打开、持续生长的东西**
- 任务有"完成"这个终态；稿件有"初稿→二稿→终稿"这种**状态演进**

现在只能用"项目 + 任务"模拟，结果是：每篇文章变成一个项目，项目里塞满"写开头""改第二段"这种伪任务。**组织成本超过收益。**

### 3.3 无字数统计

写作的人衡量进度只有两个刻度：**字数**和**完成度**。现在两个都没有（有任务完成数，但那不是写作进度）。

### 3.4 搜索撑不起素材库

`searchAll` 是子串包含 + 字段权重。问题：
- 输入两个词 → 不保证同时命中（不是 AND）
- 没有"只看笔记"的过滤
- 没有按时间/项目/标签组合筛
- 结果上限和排序对长文不友好

写作者需要"我三个月前写过一句关于雨的比喻，在哪个文件里"——现在的搜索答不了。

### 3.5 Markdown 渲染太弱

`MarkdownView` 支持：`h1-h3`、引用、代码块、行内 code、粗体、斜体、链接。
不支持：**有序/无序列表（嵌套）**、**任务清单**、表格、分隔线、图片。

写作者最常用的恰恰是列表和清单。现在粘贴一篇带列表的笔记进去，会退化成一段糊在一起的文字。

### 3.6 导出对写作者不友好

- Markdown 导出只导出**未完成任务**（`includeCompleted` 默认 false）→ 写完的稿子导不出去
- 到期**时刻**丢失（只留日期）
- 标签 `#本周` 在导入侧会被当成**项目**（往返陷阱）
- 没有"导出单篇笔记"这个动作

### 3.7 专注只有 25 分钟

番茄钟写死 25 分钟（`Pomodoro minutes=25`）。写作者的深度块通常是 45–90 分钟，25 分钟刚进入状态就被打断。

### 3.8 小刺

- 深链 `notes=` 注释承诺了但没实现
- 项目没有"字数目标/当前字数"
- 统计面板只有完成数，没有写作量

## 4. 根因（一条）

**这个项目的领域模型是"任务"，而写作需要"文本"。**

任务模型假设：一件事有标题、有截止、有状态、会完成。
文本模型需要：有正文、可编辑、有字数、可版本、能引用。

现在 `notes` 是任务的附属字段（只读），所以"文本"在系统里没有公民身份。

**两条路**：
- **A（重）**：引入独立实体 `Document`（标题/正文/字数/状态/所属项目），任务与文档并列。彻底，但要动 schema、命令、同步、UI，成本大。
- **B（轻）**：把 `notes` 升格为**一等公民**——可编辑、可全文搜、可单独导出、有字数、渲染补强。不动 schema，只补 UI 与能力。

**选 B，然后观察。** 理由：写作者 80% 的需求是"在任务上下文里写正文"，而不是"管理一堆独立文档"；B 能在 1–2 个迭代内交付，且不破坏现有同步/合并（`notes` 已经在字段级合并白名单里）。等真的出现"一篇 5 万字的东西要分章节"的需求，再上 A。

**P1 期间修掉的两个真 bug**：

1. **`📅` 污染标题**：`parseQuickAdd` 抽走日期后没清理日历 emoji，导致「导出 → 导入」后标题变成 `交稿 📅`。这是往返保真的硬伤，已修（`quick-add.ts` 清理 `📅📆🗓`）。
2. **搜索语义变化需知晓**：多词查询从"整串子串"改为 AND 后，`修复 bug` 的分数由 70 变 50（取「bug」的包含分）。旧测试断言已按新语义更新并注明原因。

**未做（诚实说明）**：P1-4 的"文档列表"没有单独做——项目详情里已有的任务列表本质上就是文档列表（每篇稿子 = 一个任务 + 正文），额外造一个"文档"视图会与现有列表重复。等真出现"一篇 5 万字要分章节"的需求，再上独立 `Document` 实体（见 §4 方案 A）。

### P2 · 深化 —— ✅ 已完成（v2.5）

| # | 改什么 | 状态 | 实现 |
|---|---|---|---|
| 8 | **素材库** | ✅ | `store/selectors/tasks.ts#getMaterials`（`status=someday`，按 `updatedAt` 倒序）+ 页面 `/materials`：三条统计（条目/有正文/总字数）+ 列表，点击进详情改状态。**不新建实体**——所谓"素材"就是"还没决定用在哪儿的东西"，与 someday 语义一致，复用可免去 schema/命令/同步/合并四层改动 |
| 9 | **写作统计（每日字数曲线）** | ✅ | `features/writing-stats.ts`：`dayKey` / `totalBodyWords` / `recordDailyWords` / `computeWritingSummary`（每日净增 = 相邻存量差；含活跃天数、最佳单日、连续天数）。存储用 `kv["writing.daily"]`（存"存量"而非"增量"——存量幂等，崩溃/重放不会算重）。页面 `/writing`：4 个 StatTile + 14 天柱状图 + 口径说明 |
| 10 | **笔记版本快照** | ✅ | 迁移 **v7** `note_versions(id, task_id, content, word_count, created_at)`；`db/note-versions.ts`：`pushNoteVersion`（保存前存**旧内容**）/ `listNoteVersions` / `clearNoteVersions`，每任务保留 **20** 条、内容相同不重复记、不参与同步（本机编辑历史）。`task.update` 在正文变更前自动调用。页面 `/history?taskId=`：列表 + 一键恢复 |

**实现时修掉的两个自身 bug**（都是测试逼出来的）：

1. **写作统计基线取错**：最初用"昨天"当基线，区间跨多天时首日 delta 会算成负数（`11-03 存量 100` 减 `11-04 存量 400`）。正确基线是**第一个数据点之前那天**。15 条测试覆盖后修正。
2. **迁移测试的硬编码版本号**：每加一个迁移就要手改三处 `toBe(6)` 之类的断言。改为引用 `LATEST_SCHEMA_VERSION` 常量后，测试自动跟随（`applied` 断言用 `LATEST - N`）。

**P2 之后，写作者动线已闭环**：记素材（收集箱/someday）→ 写正文（编辑器 + 字数）→ 找（多词 AND + 范围）→ 看进度（项目字数 + 每日曲线）→ 兜底（版本历史 + 撤销 + 回收站）→ 交付（导出正文/Markdown）。

## 6. 验收标准（写作者视角，不看代码）

- [x] 能在一个任务里写完 1500 字，中途切走再回来内容还在（编辑态草稿 + 显式保存）
- [x] 写的时候能看见字数在涨（编辑工具条实时字数 + 阅读时长）
- [x] 写完能一键看渲染效果（保存后自动切回 `MarkdownView`；有序/无序/嵌套/任务清单都不走形）
- [x] 能从项目里看到"这个项目一共写了多少字"
- [x] 专注能设 90 分钟，不被打断
- [x] 导出的 Markdown 粘到别的软件里，列表和标题还在（有序/嵌套列表 + 时刻保留 + 📅 不污染标题）
- [x] 想找三个月前写的一句话，能搜到（多词 AND + 只搜正文）
