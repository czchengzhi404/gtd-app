# GTD 清单 · 功能取舍分析（UX 视角，v2.0.0）

> 目的：从**使用者**角度判断「哪些功能该删、哪些该收敛、哪些该补」，而不是从代码角度判断「哪些好实现」。
> 每条结论都带**代码证据**，便于复核；估算值已标注「估算」。
> 结论优先级：**P0 = 影响首次使用成功率 / 每天都要忍的摩擦**，P1 = 明显提升但可等，P2 = 锦上添花。

## 1. 判断标准

一个功能要不要留，按这五条打分（任一为「否」就要质疑）：

1. **首用 3 分钟能否成功**：新用户能不能在 3 分钟内完成「记一条 → 理清一条 → 在今天就看见」。
2. **首屏控件 ≤ 2 行**：列表页第一行任务之前，最多两行控件（输入 + 筛选）。
3. **入口可被猜到**：用户想找它时，第一反应的位置就是它所在的位置（模板不该在「洞察」里）。
4. **破坏性操作可撤销**：删除、批量完成、批量移动，60 秒内能回退。
5. **新功能替代旧操作**：加法必须是「替换」，不是「并列」。并列 = 认知税。

## 3. 减法：建议删除或收敛

### 3.1 收集箱首屏 5 层控件 → 收敛到 2 层 【P0】

**问题**：进 App 第一眼是「收集箱」，但任务列表前面压了 5 行控件。按 56+56+44+40+36 ≈ **232px（估算）**，在 6.3 吋手机上约占可视高度 28%，一屏只能看到 4–5 条任务。

**证据**：`(tabs)/index.tsx` 渲染顺序为 `PageHeader → QuickAddBar → FilterBar → PerspectiveBar → ViewToggle → TaskList`。

**做法**：
- `PerspectiveBar` 收进 `FilterBar` 的「筛选」弹层（视角本质就是「已保存的筛选」）；
- `ViewToggle`（列表/看板）移到列表右上角一个图标按钮；
- 目标：**QuickAdd + 一行筛选** 两行封顶。

**收益**：首屏任务数 +40%（估算）；「收集箱」回归它唯一该做的事——看和记。

**风险**：低。视角功能仍可达，只是多一次点击。

---

### 3.2 删掉收集箱的「看板」视图 【P0】

**问题**：`InboxView = "list" | "kanban"`。收集箱里的任务**还没有状态**（未理清），而看板的价值恰恰是按状态分列。用看板看一堆未分类的东西，等于把「待办堆」变成「四列待办堆」。

**证据**：`(tabs)/index.tsx` 的 `type InboxView`；`KanbanBoard` 按 `status` 分列。

**做法**：收集箱只保留列表；看板只在**项目详情**提供（那里有明确的流程含义）。

**收益**：少一个入口、少一个「我该用哪个视图」的决策；也让「理清」成为收集箱唯一出口。

**风险**：低。若有人习惯用收集箱看板，可用「项目看板 + 一个『未理清』项目」替代。

---

### 3.3 今天 4 视图 → 手机 2 视图 【P1】

**问题**：手机上 `时间线` 是禁用态（`disabled: !isWideUp`），`日历` 在窄屏也是压缩展示。四个 tab 里有两个是「点不动 / 看不全」的，属于纯占位。

**证据**：`(tabs)/today.tsx` 的 `ViewToggle options`，`timeline` 带 `disabled`。

**做法**：手机只留 `列表 / 即将`；`日历 / 时间线` 放进右上角「更多视图」菜单（桌面端保持四选）。

**收益**：少两个点不动的按钮；今天的核心是「今天做什么」，不是「看日历」。

---

### 3.4 更多页 8 组 22 项 → 6 组 + 两个子页 【P1】

**问题**：更多页是「什么都往里塞」的典型形态：今日回顾 / 任务状态 / 洞察 / 清理 / 同步 / 数据 / 外观 / 关于，共 22 个可操作项。用户找一个设置要滚屏 + 逐行读。

**证据**：`(tabs)/more.tsx` 中 `SectionHeader × 8`、`EntryRow × 9`、`Button × 13`。

**做法**：
- 拆出 **「设置」子页**：主题 / 语言 / 通知 / 外观 / 关于；
- 拆出 **「数据」子页**：导出 ×3、导入 ×2、备份（本地/云）；
- **模板**从「洞察」移到「工具」（模板不是洞察）；
- 更多页保留 6 组：回顾 / 洞察 / 清理 / 同步 / 数据 / 设置。

**收益**：更多页一屏可扫完；「设置」这类低频项不再和「同步」这种高频项混排。

---

### 3.5 统计面板：首屏 4 个数字 → 3 个 【P2】

**问题**：`insights.tsx` 首屏 4 个 `StatTile`（今日完成/7 天完成/完成率/连续天数），下面还有趋势、项目进度、情境分布。信息都对，但**一次给太多等于没给**。

**做法**：首屏固定 3 个（今日完成 / 7 天完成率 / 逾期数），趋势与分布折叠为「展开看更多」。

**收益**：用户 3 秒能回答「我这周怎么样」。

---

### 3.6 删死代码：`Fab`、`TwoPaneLayout` 【P0，成本 10 分钟，已完成】

**证据**：对 `packages/ui/src`、`apps/mobile/src`、`apps/desktop/src` 全量做引用计数（排除自身与 `index.ts` 再导出）：

- `Fab` → 0 引用
- `TwoPaneLayout` → 0 引用
- （复核修正）`UndoBar` 是**文件名**，不是导出名；该文件导出的 `showUndo / UndoHost / listUndo …` 全都在用，**不是死代码**，已从清单移除

**做法**：删文件 / 删导出；`index.ts` 同步。**注意**：`ViewToggle`、`PerspectiveBar` 看起来像遗留，实际都在用（`today.tsx` / `index.tsx`），不要误删。

**收益**：少 2 个「看起来能配但配了没用」的 API；后来者不再纠结该用哪个。

---

### 3.7 三个导出并列 → 主推一个 【P2】

**问题**：`导出 JSON / 导出 Markdown / 导出日历(ICS)` 三个按钮同权重并排。但 95% 的场景是**备份/换机**，只有 JSON 能承担。

**做法**：主按钮「导出备份（JSON）」，其余两个收进「其他格式」。

## 4. 加法：建议新增

### P0（1–2 天量级，直接影响首次体验）

**4.1 首次启动引导（3 屏 + 示例任务，可跳过）**
- 证据：全仓搜索 `onboard / welcome / firstRun / guide` = 0 命中；新用户第一次看到的是空收集箱 + 一句话提示。
- 内容：① 这里记东西（示例：`给张总发周报 #工作 @电脑 !! 明天`）② 理清把「事」变「动作」③ 今天只看 3 条。最后一屏给「创建示例任务」按钮（可一键删）。
- 收益：把 `docs/user-feature-guide.md` 的前 3 节搬进产品，首用成功率提升最大的一步。

**4.2 空态教语法（可点击示例 chip）**
- 证据：`inbox.emptyHint` 只有「随手记点什么吧，之后再来理清」，没有教 `@ # ! 明天`。
- 做法：空态下方放 3–4 个 chip（`@电脑`、`#工作`、`!!! 明天`、`>张三`），点一下把片段填进输入框。
- 收益：把「语法表」从文档搬到第一屏，学习成本归零。

**4.3 ~~移动端导出后「分享」~~ —— 复核后撤销该项**
- 原判断：`apps/mobile/package.json` 里没有 `expo-sharing`，以为移动端只能 toast 路径。
- 复核结论：`expo-sharing@57.0.24` 声明在**仓库根** `package.json`（bun workspace 提升），
  `apps/mobile/src/platform/export-actions.ts` 已在移动端写 cache 后调用 `Sharing.shareAsync`，
  系统分享面板本来就会弹出。**无需改动**，此项从迭代 A 移除。

**4.4 批量「推迟 / 改日期」**
- 证据：`BulkActionBar` 只有 完成 / 移动 / 删除 / 清除。
- 场景：周回顾时最常见的动作是「这 12 条都推到下周」——现在只能一条条改。
- 做法：批量动作加「推迟到…」（今天/明天/下周/自选），复用 `planDeferToTomorrow` 的规划函数。

**4.5 撤销历史入口**
- 证据：`lib/undo-stack.ts` 有 `listUndo / undoDepth`，但只有提示条上的「还可撤销 N 步」能进。
- 做法：更多页加「最近操作」入口（10 条 + 一键回退），或在设置里给个开关。

### P1（一个迭代内）

**4.6 模板增强**：从项目生成模板（把整个项目的任务骨架存下来）、模板使用次数、模板删除可撤销（现在 confirm 后不可逆）。
**4.7 每周回顾提醒**：`review.tsx` 有完整六步，但没有任何提醒（通知只有到期类）。加「每周日 20:00」本地提醒，点通知直达回顾。
**4.8 同步冲突可视化**：冲突只写日志，用户看不到「哪条被覆盖了」。做法：冲突列表 + 两条记录二选一。
**4.9 搜索增强**：最近搜索、按项目/情境筛选、结果按类型分组（现在只有关键词 + 高亮）。
**4.10 回收站保留期可见**：90 天固定且不可见。做法：回收站顶部显示「删除后保留 90 天」，并提供「立即清空」。
**4.11 Android 分享接收**：`expo-linking` 已支持 `gtd://add?title=`，但系统分享菜单里没有本 App。加 share intent，把「别的 App 里看到的东西」一键存进收集箱。

### P2（有余力再做）

**4.12 大字号模式（1.15×）**：当前为防布局错乱把 `allowFontScaling` 锁死——这对**真正需要大字的人**是反效果。做法：设置里给「大字号」开关，整体按 1.15 缩放并放宽行高。
**4.13 内置 7 天路线**：把用户文档 §7 做成产品内的「新手清单」（7 个可勾选任务）。
**4.14 时间块 / 日历双向同步**：成本高（要处理冲突与重复），建议明确「暂不做」，别做半成品。

## 5. 不做清单（明确拒绝，避免反复讨论）

| 不做 | 原因 |
|---|---|
| 多人协作 / 共享清单 / 评论 | 架构前提是「单人多设备 + 修订号 LWW」，加协作等于换架构 |
| 官方账号与云服务 | 与「本地优先、无账号」的产品定位冲突 |
| AI 自动排期 | 排期规则一旦不透明，用户就不敢信；且与「确定性解析器」的设计相悖 |
| 自定义字段 / 插件系统 | 会让每个界面都要处理「未知字段」，复杂度指数上升 |
| 主题商店 | 现有「纸与墨」单一语言已经够；主题是装饰，不解决任务问题 |
| 时间块排程（P2 里的 4.14） | 只在明确要做日历时才启动，否则是半成品 |

## 7. 验收清单（无遥测，靠自己测）

本项目刻意不做遥测，所以用**可自测的硬指标**替代数据看板：

- [ ] 全新安装 → 3 分钟内能完成「记 3 条 + 理清 1 条 + 在今天就看见」
- [ ] 收集箱首屏，第一行任务出现在**屏幕上半部**（小屏 6.1" 也要满足）
- [ ] 更多页**一屏内**能扫完（≤ 12 项）
- [ ] 任意破坏性操作（删除/批量完成/批量移动）**60 秒内**可撤销
- [ ] 导出后**1 步内**能分享出去（移动端）
- [ ] 任何「看起来能点」的控件都有反馈；禁用态要说明原因（如时间线）
- [ ] 新手不看文档，也能说出「收集箱」「理清」「专注」各是干什么的
